# Протокол Nitro Console v1

`protocol_version = 1`. Машиночитаемые части: `openapi.yaml` (HTTP) и `ws-messages.schema.json` (текстовые WS-сообщения). Бинарные кадры описаны только здесь. Любое изменение — через issue `contract-change`, решение лидера и повышение версии при несовместимости.

## 1. Подключение

1. PWA раздаётся сервером: `http://<ip-ноутбука>:8765/`. Тот же origin для HTTP и WS.
2. `GET /api/v1/info` (без авторизации) → `protocol_version`, `capabilities`, `features`. Если `protocol_version` не совпадает — PWA показывает понятную ошибку и не подключается.
3. Сопряжение: на ТВ/в консоли сервера показан 6-значный код и QR. QR содержит `http://<ip>:8765/#pair=<код>` (фрагмент не уходит на сервер). PWA делает `POST /api/v1/pair {"code": "123456", "device_name": "iPhone"}` → `{"token": "...", "device_id": "..."}`. Код одноразовый, живёт 5 минут, 5 неверных попыток → новый код. После успешного сопряжения сразу выдаётся и показывается новый код. **Исключение только для мок-сервера** (`info.mock = true`): флаг `--pair-code 123456` задаёт постоянный многоразовый код без TTL и лимита попыток — для автотестов PWA; настоящий сервер такого режима не имеет.
4. Токен хранится только на телефоне (`localStorage`). HTTP: заголовок `Authorization: Bearer <token>`. **Токен никогда не передаётся в URL.**
5. WebSocket: `ws://<ip>:8765/ws`. Первое сообщение клиента — текстовое `hello` с токеном (не позже 5 с). Ответ — `welcome` или `error` + закрытие.

## 2. WebSocket

Текстовые кадры — JSON по `ws-messages.schema.json`. Бинарные кадры — ввод и служебные пакеты, little-endian. Первый байт бинарного кадра — тип.

### 2.1 Текстовые сообщения

| Направление | `type` | Назначение |
|---|---|---|
| клиент → сервер | `hello` | `token`, `protocol_version`, `client` (`platform`, `name`) |
| сервер → клиент | `welcome` | `slot` (0–3), `session_id`, `deadman_ms`, `send_hz`, `capabilities` |
| сервер → клиент | `error` | `code`, `message`; после ошибки авторизации сервер закрывает сокет кодом `4401`, при несовпадении версии — `4426`, при отсутствии свободного слота — `4409`, при нарушении рукопожатия (не `hello` первым) — `4400`, без `hello` за 5 с — `error timeout` + `4401`. Код `4000` без `error` — этот же телефон подключился заново, старое соединение закрыто (переподключаться не нужно) |
| сервер → клиент | `stats` | `rtt_ms` (замер сервера), `last_seq`, `dropped` — примерно раз в секунду |
| сервер → клиент | `event` | `name` (`console_mode`, `launch`, `devices`, `storage`) и `data` — уведомление «обнови экран» |

### 2.2 Бинарные кадры

**`0x01` PAD_STATE** (клиент → сервер), 18 байт:

| Смещение | Тип | Поле | Значение |
|---|---|---|---|
| 0 | u8 | `type` | `0x01` |
| 1 | u8 | `flags` | бит 0 — «палец на экране»; остальные 0 |
| 2 | u16 | `seq` | счётчик кадров, по модулю 65536 |
| 4 | u16 | `t` | мс по часам клиента, по модулю 65536 (для диагностики) |
| 6 | u16 | `buttons` | битовая маска, см. ниже |
| 8 | i16 | `lx` | −32768…32767, вправо = + |
| 10 | i16 | `ly` | вверх = + (как XInput) |
| 12 | i16 | `rx` | |
| 14 | i16 | `ry` | |
| 16 | u8 | `lt` | 0…255 |
| 17 | u8 | `rt` | 0…255 |

Слот определяется соединением (`welcome.slot`), а не кадром.

**Кнопки** (совпадают с XInput `wButtons`):

| Бит | Маска | Кнопка | | Бит | Маска | Кнопка |
|---|---|---|---|---|---|---|
| 0 | 0x0001 | D-pad вверх | | 8 | 0x0100 | LB |
| 1 | 0x0002 | D-pad вниз | | 9 | 0x0200 | RB |
| 2 | 0x0004 | D-pad влево | | 10 | 0x0400 | Home (Guide) |
| 3 | 0x0008 | D-pad вправо | | 11 | 0x0800 | резерв (0) |
| 4 | 0x0010 | Start | | 12 | 0x1000 | A |
| 5 | 0x0020 | Select (Back) | | 13 | 0x2000 | B |
| 6 | 0x0040 | L3 | | 14 | 0x4000 | X |
| 7 | 0x0080 | R3 | | 15 | 0x8000 | Y |

**Правила отправки.** Клиент шлёт полный снимок при каждом изменении и дополнительно 60 Гц, пока палец на экране (`welcome.send_hz`). Сервер применяет кадр, только если он новее последнего: `0 < (seq − last_seq) mod 65536 < 32768`. Старые и повторные кадры отбрасываются (`stats.dropped`). Первый кадр соединения принимается всегда.

**Deadman.** Если по слоту нет кадров `deadman_ms` (250 мс), сервер отпускает все кнопки, центрирует стики и обнуляет триггеры. Следующий кадр снова принимается как первый. При закрытии сокета — то же самое сразу.

**`0x02` PING / `0x03` PONG** (в обе стороны), 8 байт: `u8 type`, `u8 0`, `u16 id`, `u32 t_ms` (часы отправителя). Получатель PING обязан сразу ответить PONG с теми же `id` и `t_ms`. RTT = сейчас − `t_ms`. Сервер пингует клиента раз в секунду и публикует `stats.rtt_ms`; клиент может пинговать сам.

**`0x10` RUMBLE** (сервер → клиент), 4 байта: `u8 type`, `u8 0`, `u8 large`, `u8 small` (0…255). Клиент без вибрации показывает визуальный отклик. Появится в M2 (`features.rumble`).

Неизвестный тип или неверная длина бинарного кадра → кадр игнорируется, соединение не рвётся.

## 3. HTTP

Базовый путь `/api/v1`, JSON, ошибки — `{"error": {"code": "...", "message": "..."}}`. Полное описание — `openapi.yaml`.

| Метод | Путь | Авторизация | Назначение |
|---|---|---|---|
| GET | `/info` | нет | версия, возможности, feature flags |
| POST | `/pair` | нет (код) | обмен кода на токен |
| GET | `/games` | да | установленные игры |
| GET | `/games/{appid}/cover` | да | обложка (image/*) или 404 |
| POST | `/games/{appid}/launch` | да | запуск через Steam, ответ 202 |
| GET/POST | `/console-mode` | да | состояние / включить-выключить режим приставки (202) |
| GET | `/system` | да | громкость |
| POST | `/system/volume` | да | громкость 0–100, mute |
| POST | `/system/power` | да | `sleep|restart|shutdown`, обязательно `confirm: true` |
| GET | `/devices` | да | подключённые устройства ввода |
| GET | `/storage` | да | диски и библиотеки Steam |

**Расширяемость UI.** Устройства, хранилище и бэкенды вывода описываются данными (`kind`, `capabilities`), а не зашитыми типами. Незаконченное скрывается по `info.features`.
