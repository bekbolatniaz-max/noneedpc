# Nitro Console — Архитектура v1

> Положить в репозиторий как `docs/architecture.md`. Это главный документ проекта: промпты A и B ссылаются на него.

## 1. Что строим

Свою «приставку», похожую на PlayStation: игровой ноутбук подключается по HDMI к любому ТВ, **телефон работает геймпадом и пультом**, игры берутся из Steam. Сначала лёгкие одиночные игры.

Принципы (по приоритету):

1. **Телефон = геймпад.** Это основная фишка, поэтому главная метрика проекта — **задержка ввода**.
2. **Быстрый MVP.** Сначала играем, потом улучшаем. Всё, что не нужно для первой игры, откладывается.
3. **Работает у обоих.** iPhone (Safari) и Google Pixel (Chrome), разные ТВ. Ноутбук подключается к ТВ не постоянно.
4. **Форк под себя.** Каждый скачивает проект и настраивает свой экземпляр через конфиг. Никаких зашитых имён, IP и моделей ТВ.
5. **Расширяемость.** Новый способ ввода, новый «выход» (драйвер), новый диск подключаются плагином без правок ядра.
6. **Экономия лимитов.** Подписки Claude и Codex по $20, поэтому проверки делаются точечно.

## 4. Ключевой вопрос: нужен ли драйвер?

Игры читают геймпад через XInput, DirectInput или Steam Input. Чтобы ноутбук «увидел» геймпад, которого физически нет, нужен один из вариантов ниже.

| Вариант | Драйвер на ноуте | Аналоговые стики | Сложность | Вердикт |
|---|---|---|---|---|
| **A. ViGEmBus** (готовый открытый драйвер, подписан Microsoft) + `vgamepad` | да, один раз ставится готовый | ✅ полноценный Xbox 360 | низкая | **MVP по умолчанию.** Не развивается с 2023 года, но работает. Его задержка ничтожна по сравнению с Wi-Fi, оптимизировать там нечего |
| **B. Клавиатура и мышь** через `SendInput` (Windows API) | **нет** | ❌ ходьба только на 100%, камера через мышь | низкая | **Запасной вариант без драйвера.** Большинство ПК-игр его поддерживают, но в игре будут подсказки клавиатуры |
| **C. Windows InputInjector** (`InjectGamepadInput`) | нет | ✅ | средняя | **Эксперимент на 1 час.** Насколько известно, классические XInput-игры его не видят. Проверить, не закладываться |
| **D. Bluetooth HID с телефона** | **нет** | ✅ | средняя-высокая | **Только Android (Pixel).** Android 9+ умеет прикидываться BT-геймпадом (`BluetoothHidDevice`), но нужно нативное приложение, PWA так не может. **iPhone так не умеет**: iOS не даёт приложениям изображать BT-клавиатуру или геймпад. Этап M3 |
| **E. Свой драйвер ядра** | да, свой | ✅ | очень высокая | **Нет.** Нужна подпись Microsoft (юрлицо и EV-сертификат) или тестовый режим Windows, который снижает защиту и ломает античиты. Месяцы работы без выигрыша |

**Решение:** интерфейс `OutputBackend`, у которого несколько плагинов. В MVP используется `vigem`, рядом готовый `kbm` как запасной без драйвера. `injector` — эксперимент. Bluetooth для Pixel — отдельный трек M3. Пользователь выбирает бэкенд в конфиге или в PWA.

## 5. Ввод с телефона и задержка

**Бюджет задержки** (без учёта игры и ТВ): цель меньше 30 мс от касания до виртуального геймпада. Сервер замеряет и показывает RTT в PWA.

**Протокол ввода: «снимок состояния», а не события.**
- Телефон шлёт полное состояние геймпада: `seq`, `t`, кнопки (битовая маска `uint16`), стики (4 × `int16`), триггеры (2 × `uint8`). Это ~16 байт в бинарном виде.
- Отправка при каждом изменении плюс 60 Гц, пока палец на экране. Сервер применяет только самый свежий `seq`, поэтому потеря или опоздание пакета ничего не ломает.
- **Deadman-таймер:** если 250 мс нет пакетов, сервер отпускает все кнопки и центрирует стики. Залипших кнопок не будет.

**Транспорт:**
- **v1 (MVP):** WebSocket, бинарные кадры, `TCP_NODELAY`. Просто, работает везде.
- **v2:** WebRTC DataChannel (`ordered:false, maxRetransmits:0`), сигнализация через тот же WS. Убирает задержки от повторной отправки по TCP при плохом Wi-Fi. Включается после замеров, если v1 не устраивает.

**Сеть:** Wi-Fi 5 ГГц, роутер рядом. Если домашний Wi-Fi плохой, можно включить на ноутбуке «Мобильный хот-спот» и подключить телефон к нему напрямую. Это отдельный режим в `ConsoleMode`.

**Вибрация:** игра → ViGEm (callback rumble) → сервер → телефон. На Android работает `navigator.vibrate`, на iPhone Vibration API нет, поэтому там вместо вибрации визуальная индикация. Возможности определяются автоматически (`capabilities`).

**HTTPS:** Service Worker, Wake Lock и полноценная PWA требуют защищённого контекста, а `http://192.168.x.x` им не является.
- **MVP:** обычный HTTP. Геймпад, WebSocket и касания работают. Экран может гаснуть, поэтому в инструкции написано «увеличь автоблокировку». На iPhone можно добавить на домашний экран для полноэкранного режима.
- **M2:** локальный центр сертификации (`mkcert`), установка его сертификата на iPhone и Pixel, HTTPS. После этого работают Wake Lock и установка PWA.

## 6. Режим консоли (ноутбук подключается не постоянно)

`ConsoleModeService` с двумя командами, которые вызываются с телефона, ярлыком на рабочем столе или горячей клавишей:

**Включить «Приставку»:**
1. Сохранить снимок текущих настроек (для отката).
2. Экран только на ТВ (`DisplaySwitch /external`), разрешение и частота по профилю дисплея.
3. Звук через HDMI.
4. План питания «приставка»: не засыпать от сети, крышку закрывать не рекомендуется (охлаждение).
5. Запустить Steam Big Picture (`steam://open/bigpicture`).
6. Запустить сервер и показать на ТВ QR-код для сопряжения.

**Выключить:** вернуть всё из снимка.

**Профили дисплея** (`config/displays/*.yaml`): ТВ определяется по EDID (производитель и модель). Для ТВ лидера и ТВ друга получаются разные профили, а для нового ТВ создаётся профиль по умолчанию «как есть». Никаких зашитых моделей.

## 7. Остальные сервисы

- **Library/Launch:** чтение `libraryfolders.vdf` и `appmanifest_*.acf` (только чтение), список игр, обложки из локального кэша Steam, запуск через `steam://rungameid/<appid>`.
- **System:** громкость, сон, перезагрузка, выключение. Опасные действия только с подтверждением в PWA.
- **Storage (расширение):** интерфейс `StorageProvider`. Показывает диски, свободное место и игры по дискам, предупреждает о нехватке места. Если внешний диск отключён, его игры помечаются «недоступно». Новая библиотека Steam добавляется **штатным меню Steam**, сервис только подсказывает.
- **Pairing/Auth:** QR-код с одноразовым токеном, слушаем только локальную сеть, правило брандмауэра только для частного профиля сети.
- **Config:** `config/default.yaml` лежит в репозитории, `config/local.yaml` в `.gitignore` (у каждого свой: бэкенд вывода, раскладка, профили).

## 8. Точки расширения

| Интерфейс | Плагины сейчас | Плагины потом |
|---|---|---|
| `InputSource` | `pwa_ws` | `pwa_webrtc`, `physical_pad` (SDL2: Xbox, DualSense и другие) |
| `OutputBackend` | `vigem`, `kbm`, `mock` | `injector`, `vigem_ds4` (PlayStation-кнопки) |
| `StorageProvider` | `windows_volumes` | сетевой диск |
| Профили | раскладка PWA, дисплеи | гироскоп, макросы |

Правило: **ядро не знает о конкретных типах устройств.** Новый плагин = один файл + регистрация в `plugins/__init__.py`. Физический геймпад, который Steam видит сам, сервер по умолчанию только отображает (режим `observe`), чтобы не было двойного ввода.

Апгрейд памяти (RAM 32 ГБ, второй M.2) описан в `docs/hardware-upgrades.md`. Это инструкция, а не код.

## 10. Этапы

| Этап | Цель | Лидер (бэкенд) | Друг (фронтенд) |
|---|---|---|---|
| **M0** (1 вечер) | каркас | репозиторий, контракт v1, мок-сервер, проверка цепочки Codex | запускает мок, каркас PWA |
| **M1 MVP** (1–2 выходных) | **играем!** | WS-сервер, `vigem`, deadman, лаунчер, запуск игры, скрипт режима консоли | экранный геймпад, сопряжение, список игр, индикатор RTT |
| **M2** (комфорт) | удобно | `kbm` без драйвера, эксперимент `injector`, HTTPS, вибрация, Storage, профили дисплеев, автозапуск | Wake Lock, вибрация на Android, настройки раскладки, экран хранилища |
| **M3** (расширения) | фишки | WebRTC, физические геймпады (SDL2), `vigem_ds4` | по желанию: Android-приложение BT-геймпад для Pixel |

**Критерий MVP:** подключил ноутбук к ТВ → на телефоне нажал «Приставка» → выбрал лёгкую игру → играешь с телефона, без мыши и клавиатуры.

## 11. Риски

| Риск | Что делаем |
|---|---|
| Задержка Wi-Fi ощутима | протокол снимков, замер RTT, 5 ГГц или хот-спот, WebRTC в M3 |
| ViGEmBus устарел | вывод через плагины, есть `kbm` без драйвера |
| Сенсорное управление неудобно в динамичных играх | начинаем с лёгких игр, настраиваемая раскладка, физический геймпад в M3 |
| iOS ограничивает PWA (нет вибрации, нужен HTTPS) | определение возможностей, HTTPS в M2 |
| Лимиты подписок $20 | Codex только на ключевых задачах, Sonnet для рутины |
| Перегрев в режиме приставки | профиль Nitro Sense, крышку не закрывать, подставка |
| Место на SSD 512 ГБ | лёгкие игры сначала, второй M.2 внутрь (слот есть) |
