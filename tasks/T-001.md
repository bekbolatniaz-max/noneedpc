# T-001 · M0: каркас, контракт v1, мок-сервер

Ветка: `feat/be-T001-m0-skeleton` · Исполнитель: лидер (Claude Code) · Проверка: Codex

## Цель
Друг может начать PWA против мок-сервера без драйвера и Steam; ядро готово к плагинам M1.

## Критерии
- **AC-1** (auto) Структура репозитория по разделу 9 архитектуры в части M0 и зоны лидера; `CLAUDE.md`, `PROGRESS.md`, `DECISIONS.md`, `docs/extending.md` есть. Вне M0: `pwa/` (зона друга, T-2xx), `docs/hardware-upgrades.md` (M2).
- **AC-2** (auto) Контракт v1: бинарный снимок геймпада, PING/PONG, RUMBLE, текстовые WS-сообщения (JSON Schema), HTTP (OpenAPI): info/capabilities/protocol_version, pair, games, cover, launch, console-mode, system (volume, power), devices, storage.
- **AC-3** (auto) Интерфейсы `InputSource`, `OutputBackend`, `StorageProvider`; реестр плагинов; ядро не импортирует плагины (тест).
- **AC-4** (auto) `InputRouter`: применяется только самый свежий `seq` (с переполнением u16), deadman 250 мс отпускает всё, закрытие сокета отпускает всё.
- **AC-5** (auto) Сопряжение: одноразовый 6-значный код с TTL и лимитом попыток, токен только в заголовке / `hello`, хранятся только хэши, сравнение за постоянное время.
- **AC-6** (auto) Мок-сервер `python -m server.mock` реализует каждый маршрут из OpenAPI; все ответы проходят схему (контрактные тесты); WS-сообщения проходят JSON Schema.
- **AC-7** (auto) Мок не делает системных изменений (питание/громкость только в памяти).
- **AC-8** (auto) `.gitignore` для `config/local.yaml` и секретов, проверка `.verify/secret_scan.py`.
- **AC-9** (manual) Друг запускает мок на своём ноутбуке и получает `/api/v1/info` с телефона по Wi-Fi — `manual-checks/T-001.md`.
